# DayOS Product Spec

> 상태: 초안 v0.1 (2026-11-01) · 근거: 제품 오너의 답변. 오너가 정하지 않은 항목은 **미정**으로 표시했다.
> 이 문서가 바뀌면 `docs/ARCHITECTURE.md`와 `CLAUDE.md`도 같이 확인한다.

## 1. 한 줄 정의

일정은 **사용자가 직접** 관리하고, AI는 **요청받았을 때만** 준비 사항과 다음 행동을 **추천**하며, 일정을 바꾸는 일은 **사용자가 승인한 것만** 실행하는 웹 기반 AI Planner.

**포지셔닝:** 단순한 AI Calendar가 아니라 **Context-Aware Personalized AI Planner**. 사용자가 직접 짠 일정과 개인 선호·우선순위·피드백을 바탕으로, 요청받았을 때 맞춤 추천을 한다. Personalization은 핵심 기능이며 요구사항은 `docs/PERSONALIZATION.md`, 평가는 `docs/EVALUATION.md`, 예시는 `docs/SCENARIOS.md`에 있다.

## 2. 핵심 원칙 (바꾸지 않는 규칙)

1. **사용자 주도 캘린더.** 일정의 생성·수정·삭제는 사용자가 한다.
2. **AI가 일정을 임의로 재배치하지 않는다.** AI의 출력은 항상 "제안"이고, 사용자가 승인하기 전에는 일정 데이터가 바뀌지 않는다.
3. **추천은 요청했을 때만.** 사용자가 요청하지 않으면 AI를 호출하지 않는다. (자동 알림은 AI 없이 규칙으로 동작한다.)
4. **개인 일정 데이터는 동의 없이 외부 API로 보내지 않는다.** 동의는 모델(제공자)별로 따로 받고, 언제든 철회할 수 있다.
5. **특정 회사·모델에 종속되지 않는다** (Model-Agnostic).
6. **데이터 최소화·분리·삭제.** 사용자별로 데이터를 분리하고, 사용자가 자기 데이터를 삭제할 수 있다.

## 3. 대상 사용자

- 초기 타깃: **일반 개인 사용자(B2C)**.
- MVP는 제품 오너가 혼자 먼저 사용하며 검증하지만, 이후 다른 사용자가 가입하는 실제 서비스를 목표로 한다.
- **MVP 범위 밖:** 팀 일정 공유, 조직 권한 관리, 기업용 기능.
- 비용: 무료 인프라를 우선 활용하고, 불필요한 기능·비용을 추가하지 않는다.

## 4. MVP 기능

### 4.1 캘린더 (사용자 직접 추가·수정)
- 일정 생성, 수정, 삭제, 조회 (일/주/월 보기는 **미정** — 가장 단순한 것부터)
- 필드: 제목, 시작/종료 시각, 메모, 위치(선택)
- 시간대 처리 규칙은 `ARCHITECTURE.md`의 열린 질문 참조

### 4.2 자동 알림
- 일정 시작 전, 사용자가 정한 규칙(예: 10분 전)에 따라 알림
- **AI 없이** 동작한다 (규칙 기반)
- 알림 채널(브라우저 푸시, 이메일 등)은 **미정**

### 4.3 Context-Aware AI Recommendation (선택적 AI 추천)
사용자가 추천을 **요청**하면, **현재 및 미래 일정**을 바탕으로 다음을 추천한다.

| 추천 종류 | 설명 |
|---|---|
| 필요한 준비 사항 | 예: 내일 발표 일정 → 자료 최종 점검, 이동 시간 확보 |
| 다음 행동 | 예: 지금 비는 시간에 하면 좋은 일 |
| AI가 대신 수행할 수 있는 업무 | 예: 회의 안건 초안 작성, 참석자에게 보낼 메시지 초안 |

- 추천은 **카드 형태의 제안**으로 보여 주고, 사용자는 수락/거절/무시할 수 있다.
- 일정 변경이 필요한 추천은 "변경안"으로 표시하고, **수락해야만** 적용한다 (원칙 2).
- AI가 "대신 수행"하는 업무는 **초안 생성까지**가 MVP 범위다. 메시지 전송 등 외부에 영향을 주는 실행은 MVP 범위 밖(미정).
- 추천 요청 시 어떤 일정 정보가 모델에 전달되는지 **사용자에게 미리 보여 준다.**
- **개인화:** 추천은 일정뿐 아니라 사용자가 직접 입력한 선호·우선순위와 이전 제안에 대한 수락/거절 피드백을 참고한다 (`PERSONALIZATION.md`). 사용자가 요청하지 않으면 추천을 만들지 않는다.
- **실행 기록:** 승인된 제안이 적용되면 제안 ID, 승인 시각, 변경 요약, 결과를 기록하고 사용자에게 보여 준다. 외부 서비스 호출은 MVP 범위 밖이며, 생기면 같은 승인·기록 절차를 따른다.

## 5. MVP 범위 밖

- 승인 기반 AI Agent의 **자동 실행** (예: 승인 후 외부 서비스에 메시지 전송, 일정 자동 생성 등) — 설계 방향만 문서화하고 구현은 이후
- 팀·조직 기능, 다른 캘린더(Google 등) 연동, 모바일 네이티브 앱
- Model Router의 자동 선택 (설계만 열어 둠)
- 로컬 모델(A.X 등) 실제 통합 — 평가 후보로 등록만 한다

## 6. 플랫폼

- **웹앱.** 브라우저에서 URL로 접속.
- 개발 중 화면은 스크린샷으로 확인하고 PR에 첨부한다.

## 7. 모델 정책 요약

- MVP는 **비용과 성능을 고려해 적절한 API 모델 하나**로 시작한다. (어떤 모델인지는 평가 후 결정 — **미정**)
- Local Model Adapter와 Cloud API Adapter를 분리해 나중에 모델을 쉽게 추가·교체한다. (`ARCHITECTURE.md`)
- SKT A.X는 중요한 연구·평가 후보이며 SKT 관련 AI Agent 포트폴리오에도 활용한다. 다만 제품은 A.X 데모가 아니라 **실제 사용자에게 제공하는 AI Planner/Agent 서비스**다.
- 모델 후보: SKT A.X, OpenAI, Claude, Gemini, Qwen 등. 평가 기준은 `docs/MODEL_REGISTRY.md`.

## 8. 개인정보 요구사항

- 사용자별 데이터 분리 (다른 사용자의 일정이 보이면 안 됨)
- 인증 (가입/로그인 방식은 **미정**)
- 사용자 요청 시 계정·일정·AI 요청 기록 삭제
- 외부 API 전송 전 동의, 모델 제공자별 데이터 처리 정책(학습 사용 여부, 보관 기간) 기록
- AI 요청 로그에는 일정 원문 대신 필요한 최소 정보만 남긴다 (**상세 기준 미정**)

## 9. 성공 기준 (MVP, 초안 — 오너 확인 필요)

- 오너가 한 주 동안 실제 일정을 이 앱으로 관리할 수 있다
- 알림이 설정한 시각에 도착한다
- AI 추천을 요청해 받은 제안 중 쓸 만한 것의 비율을 기록한다 (기준값 **미정**). 관련성·실행 가능성·승인율·부적절한 추천·응답 시간을 `EVALUATION.md` 기준으로 본다
- AI가 승인 없이 일정을 바꾼 경우 **0건**
