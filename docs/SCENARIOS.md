# DayOS 사용자 시나리오

> 상태: 초안 v0.1 (2026-11-08) · **예시이며 가상의 인물·데이터다.** 실제 동작하는 제품이 아직 없다. 추천 문구는 개인화가 어떻게 이어지는지 보여 주는 설명용이다.

## 시나리오 1 — 내일 발표 준비

**입력**
- 일정: 내일 14:00–15:00 "분기 발표" (사용자 입력), 오늘 16:00–17:00 "팀 회의"
- 선호(직접 입력): 발표 전날 저녁까지 자료 점검 선호, 이동 시간 30분 여유
- 우선순위: 분기 발표 = 높음

**사용자가 "추천 받기"를 누름 → 전송 필드 확인 → 동의**

**개인화 추천 (제안)**
- 준비 사항: "발표 자료 최종 점검 — 오늘 17:00 이후 비는 시간 사용" (선호 + 우선순위 반영)
- 일정 변경안: "내일 13:30에 '이동·준비' 블록 추가" → **승인해야만 반영**
- AI 대행: "발표 시작 인사 문장 초안" (초안만)

**결과:** 사용자가 변경안 수락, 초안 무시. 수락/무시가 피드백으로 기록된다.

## 시나리오 2 — 비는 시간에 할 일

**입력**
- 일정: 오늘 오전 회의 후 11:00–13:00 비어 있음
- 선호: "집중 작업은 오전에"
- 이전 피드백: 최근 "운동 제안"을 두 번 거절 (사유: 오늘은 불가)

**추천 (제안)**
- 다음 행동: "11:00–12:30 집중 작업 블록 — 이번 주 마감인 보고서"
- 운동 제안은 제외 (최근 거절 반영)

**결과:** 사용자는 제안을 수락하지 않고 닫는다. 일정은 그대로 유지된다. (무시도 피드백)

## 시나리오 3 — 요청하지 않으면 아무 일도 없다

**입력:** 사용자가 일정을 직접 추가하고 알림만 사용.

**동작**
- 10분 전 알림은 규칙대로 발송된다 (AI 미사용).
- 추천 버튼을 누르지 않았으므로 AI 호출, 외부 전송, 제안 생성이 **없다**.

## Concept Wireframe

> **개념 도식(Concept Wireframe)이다. 실제 제품 화면이 아니며, 구현된 UI는 없다.** 구조 이해용이다.

```text
┌ DayOS ───────────────────────────────┐
│ [일정 보기]            [추천 받기] ← 눌러야 AI 호출 │
│ 내일                                   │
│  14:00 분기 발표                       │
├ 추천 제안 (요청 후) ──────────────────┤
│ ┌ 준비: 자료 최종 점검 (오늘 17:00~) ┐ │
│ │ 변경안: 13:30 이동·준비 블록 추가   │ │
│ │ [수락] [거절] [나중에]              │ │
│ └ 수락해야 일정에 반영됩니다 ────────┘ │
└────────────────────────────────────────┘
```

화면 이미지가 필요하면 별도 PR에서 Concept 도식임을 표시해 제안한다.
