# DayOS Personalization (요구사항 수준)

> 상태: 초안 v0.1 (2026-11-08) · **기획 문서이며 구현된 코드는 없다.**
> 이 문서는 "무엇을 개인화하는가"만 다룬다. 신호별 가중치, 순위 결정 방식, 프롬프트 같은 **내부 로직은 공개 저장소에 두지 않는다** (`DOCUMENT_CLASSIFICATION.md`).
> 상위 문서: `PRODUCT_SPEC.md`. 평가는 `EVALUATION.md`, 예시는 `SCENARIOS.md`.

## 1. 정의

DayOS는 AI가 일정을 대신 짜 주는 캘린더가 아니라, **사용자가 직접 짠 일정과 사용자의 맥락을 이해해, 요청받았을 때 그 사람에게 맞는 준비 사항과 다음 행동을 제안하는 Context-Aware Personalized AI Planner**다.

- 일정은 사용자가 만든다. (바뀌지 않음)
- 개인화는 **추천의 내용을 고르는 데** 쓰이고, 일정을 바꾸는 권한으로 이어지지 않는다.
- 추천은 사용자가 요청했을 때만 생성한다. (바뀌지 않음)

## 2. 개인화에 쓰는 정보 (신호)

| 신호 | 예 | 출처 | 비고 |
|---|---|---|---|
| 현재·미래 일정 | 내일 14시 발표, 이번 주 마감 | 사용자가 입력한 캘린더 | 추천 요청 시 읽기 전용으로 전달 |
| 개인 선호 | 아침형, 회의 사이 15분 여유 선호, 알림 문체 | 사용자가 설정 화면에서 **직접 입력** | 추론으로 채우지 않는다 (MVP) |
| 우선순위 | 일정/할 일별 중요도 표시 | 사용자가 직접 표시 | 표시가 없으면 "미지정"으로 다룬다 |
| 이전 사용자 피드백 | 제안을 수락/거절/무시, 거절 사유 선택 | 제안 카드의 사용자 조작 | 다음 추천의 참고 자료. 일정 권한과 무관 |

**쓰지 않는 것:** 사용자가 입력하지 않은 외부 계정 데이터, 위치 추적, 다른 사용자의 데이터, 일정 원문의 장기 학습 저장.

## 3. 개인화 방식 (MVP 방향, 제안)

1. **요청 시점에 맥락 묶음(Context Bundle)을 만든다.** 대상 기간의 일정 + 선호 + 우선순위 + 최근 피드백 요약을 최소 필드로 구성한다.
2. **사용자에게 미리 보여 준다.** 어떤 필드가 모델에 가는지 확인 후 전송 (Consent Gate, `ARCHITECTURE.md` §2.2).
3. **모델은 제안만 반환한다.** 구조화된 Proposal 형태.
4. **피드백은 규칙 기반 요약으로 반영한다.** MVP에서는 모델 재학습·파인튜닝을 하지 않는다. 예: "최근 거절된 제안 유형" 요약을 다음 요청의 맥락에 포함.
5. **사용자가 개인화 정보를 보고 고치고 지울 수 있다.** 선호·피드백 기록은 삭제 대상에 포함한다.

> 구체적 요약 규칙, 순위·필터링 방식, 프롬프트 설계는 비공개 문서에서 관리한다. 여기서 정하지 않는다.

## 4. 추천 종류와 "제안 vs 실행"

| 종류 | 설명 | 결과물 | 승인 필요 |
|---|---|---|---|
| 준비 사항 | 일정 전에 필요한 일 | 체크리스트 제안 | 일정/할 일에 반영할 때 |
| 다음 행동 | 지금 비는 시간에 할 일 | 행동 제안 카드 | 일정에 반영할 때 |
| AI 대행 업무 | 초안 작성 등 | **초안 텍스트까지** (MVP) | 초안 확인은 불필요, **외부 전송·실행은 MVP 범위 밖** |
| 일정 변경안 | 이동·추가·삭제 제안 | 변경안(Diff) | **항상 필요** |

### 제안과 실행의 구분

- **제안(Proposal):** AI가 만든 데이터. 저장만 되고 아무것도 바꾸지 않는다.
- **실행(Execution):** 사용자가 승인한 제안을 시스템이 적용하는 행위. 별도 기록을 남긴다.
- 승인 대상: 일정 변경, **외부 서비스 호출(향후)**, 중요한 작업. 외부 호출은 MVP에 없고, 생기면 같은 승인 절차를 따른다.
- 승인 화면은 **무엇이 어떻게 바뀌는지**를 보여 주고, 실행 후 **결과(성공/실패/되돌림)**를 사용자에게 보여 준다.
- 실행 기록 항목: 제안 ID, 승인 시각, 승인한 사용자, 적용된 변경 요약, 결과, 되돌림 여부. (일정 원문 복제는 최소화)

## 5. 요청 없는 AI 추천 금지

- AI는 사용자가 "추천 받기"를 누르기 전에는 호출되지 않는다. 앱을 열 때 자동 추천, 푸시로 추천 강요, 일정 입력 중 끼어들기를 하지 않는다.
- 자동 알림은 규칙 기반이며 AI를 쓰지 않는다.
- (미정) 사용자가 명시적으로 켜는 선택 기능으로 "아침 요약 추천"을 허용할지는 오너 결정 사항이다. 기본값은 꺼짐.

## 6. 개인정보·접근 권한

- 모든 개인화 데이터(선호, 우선순위, 피드백, 제안, 실행 기록)는 **사용자별로 분리**하고 본인만 접근한다.
- 개인화 데이터도 삭제 요청 시 함께 삭제한다. 보관 기간은 **미정**.
- 외부 API로 가는 맥락은 모델 제공자별 동의 후에만 전송한다.
- 로컬 모델 사용 시에도 어떤 데이터가 모델에 들어가는지 동일하게 표시한다.

## 7. Model-Agnostic과 로컬/클라우드 선택

- 개인화 로직(맥락 묶음 구성, 피드백 요약)은 **모델과 독립**이다. 모델 교체가 개인화 데이터를 바꾸지 않는다.
- 모델은 `ModelAdapter` 뒤에 있고, 기본은 Cloud API 모델 하나(MVP).
- 개인정보 민감도가 높은 요청에 로컬 모델을 쓰는 선택은 Router 설계 후보이며 MVP 범위 밖. 어떤 모델에 보냈는지는 제안·로그에 모델 ID로 남긴다.
