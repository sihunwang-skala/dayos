# DayOS 개인화 평가 설계

> 상태: 초안 v0.1 (2026-11-08) · 기획 단계. **측정된 결과는 아직 없다.** 목표값은 모두 `미정`이다.
> 공식 Benchmark와 DayOS 자체 평가는 분리한다 (`MODEL_REGISTRY.md` §4–5). 이 문서는 후자의 설계다.

## 1. 평가 항목

| 항목 | 질문 | 측정 방법 | 목표 |
|---|---|---|---|
| 관련성 (Relevance) | 이 추천이 이 사용자의 이 일정·선호에 맞는가 | 평가 케이스별 1–5점 (사람 평가) | 미정 |
| 실행 가능성 (Feasibility) | 주어진 시간·일정 안에서 실제로 할 수 있는가 | 이진 판정 + 사유 (충돌 일정, 시간 부족 등) | 미정 |
| 사용자 승인율 | 제안을 수락한 비율 | 수락 ÷ (수락+거절+무시), 제안 종류별 | 미정 |
| 부적절한 추천 | 해로운/불쾌한/선호 위반/금지 규칙 위반 | 건수와 유형. **승인 없이 일정 변경 시도는 0건이어야 함** | 일정 변경 시도 0, 나머지 미정 |
| 응답 시간 | 요청부터 제안 표시까지 | p50 / p95 (초) | 미정 |

보조: 요청당 비용, 개인화 효과(개인화 on/off 비교 관련성 차이).

## 2. 평가 방법

- **고정 평가셋:** 일정 + 선호 + 우선순위 + 피드백 이력으로 이루어진 케이스를 만든다. 모든 후보 모델에 **같은 케이스**를 쓴다.
- **합성 데이터만 사용:** 실제 개인 일정은 평가셋에 넣지 않는다. 오너가 직접 쓰는 실사용 기록은 별도 집계로만 본다.
- **개인화 효과 확인:** 같은 일정에 선호/피드백을 넣은 경우와 뺀 경우를 비교한다.
- **규칙 위반 검사:** 출력에 일정 직접 변경, 승인 우회, 동의 없는 외부 전송 요구가 있는지 자동 검사한다.
- **실사용 지표:** 앱 사용 시작 후 승인율과 거절 사유를 집계한다. 표본이 1명이면 통계적 결론을 내리지 않고 참고만 한다.

## 3. 기록 위치

- 모델별 결과는 `MODEL_REGISTRY.md`의 자체 평가 표에 기록한다. 공식 수치와 섞지 않는다.
- 평가 케이스 원본과 정답 기준은 비공개 관리 대상이다 (`DOCUMENT_CLASSIFICATION.md`).

## 4. 미확정

- 목표 수치 전체 (오너 합의 필요)
- 평가자 (오너 단독인지, 추가 평가자가 있는지)
- 케이스 수와 한국어/영어 비율
